# 0.1.0-rc.5 验证记录

日期：2026-11-26。环境：Windows、Node.js 24.22.1、Magpie 0.1.4827。测试使用独立配置、本机模拟千刀和虚构凭据。

## 核心逻辑

28 项测试通过，覆盖默认 7 次与限流间隔、错误分类、预算共享、同时重复调用、整段缓存、上下文超限、无请求标记的单次发送、跨实例并发、调低上限、队列取消与到期、Retry-After、上游取消、请求字段恢复、地址热改、手填模型、设置页保存、用户配置保留、模型移除、能力声明保留和设置端口占用时的聊天可用性。

模型与余额测试覆盖原生模型钩子、候选列表替换、关闭时保留列表、账号和地址隔离、重启后读取已保存模型、取消查询、真实零余额、关闭时查询失败、Key 额度与套餐用量，以及 HTML 关闭页分类。

## 真实宿主

- 无凭据时可加载插件；纯 Key 登录后内置及手填模型可收到正文。
- 原生“获取模型”接口返回最新上游候选，不代替用户保存新增勾选；原生保存接口能保存所选模型。
- 关闭时保留候选列表及已有勾选，不标记账号失效；重新开放并刷新后移除下线的上游模型，手填模型仍保留。
- 用量接口显示模拟余额 $12.50；查询失败时 Magpie 保留旧值并显示读取错误，不改成零余额。
- 原始 UA、会话头、缓存键、加密推理内容和 additional_tools 保留；选择的推理强度到达上游。
- Magpie 原生 Fast API 可对内置及手填模型开启 Priority，客户端不提供服务等级时同样生效；关闭后取消强制 Priority，重试保留原等级。
- 明确 Fast 拒绝只向上游发送一次，不降级重发，下一条 Fast 请求仍使用 Priority。
- 设置页保存后改变实际 Base URL；总并发热改为 1 后，四个并行请求最多一个在途。
- 同一宿主内删除设置页模型后刷新列表，已删除模型消失；供应商中手填的其他模型保留。
- 插件宿主重载时，已有请求完成，新宿主等待共享名额，没有超过总并发 1。
- 上下文超限以 `response.failed context_length_exceeded` 交付，一次上游发送。
- 持续 429 在宿主重复调用下仍只发送测试配置的 3 次。
- HTML 关闭页最多发送测试配置的 3 次，不作为正常回答交付；重新开放后原账号可以继续请求。
- 客户端取消关闭上游连接。

发布包验收使用同一归档内的实现，隔离入口将重试次数改为 3、缩短等待以观察两层计数。默认 7 次和正式间隔由核心测试验证。

## 界面

供应商先全选四个候选并保存，再取消其中三个，仅保留 `gpt-6-astra`；保存并重新打开后仍只勾选 Astra。旧候选记录仅包含 Astra 时也验证了相同语义，刷新新增候选不会自动勾选。

所有已选模型暂时下架后，宿主恢复原选择时仍只勾选原模型，同期新开放的其他模型保持未选中。

设置页中输入新 URL 和并发 3，在保持页面打开时重启服务，随后点击保存成功；重新打开后仍显示新 URL 和 3。无效页面凭据返回“本次修改尚未保存”的提示。

在 `sandbox="allow-scripts"` 的 iframe 中打开实际设置页，点击保存后核对磁盘上的 Base URL 和并发；刷新页面后数值保留。并发填 0 时不写入，填有效值后按回车可以保存。

在隔离的 Magpie 0.1.4827 中从侧栏打开 dao，设置从空地址开始；浏览器点击保存后显示“已保存，设置已生效”。磁盘配置与输入一致，Provider 随后向该地址的 `/v1/responses` 发送请求并收到 200。

页面以普通按钮处理保存，逐项调用输入校验，不依赖浏览器表单提交。回归入口为 `tests/settings-browser-fixture.mjs` 和 `tests/settings-browser.mjs`；`QIANDAO_UI_MODE=1` 将浏览器保存与真实宿主请求验证连接起来。

## 已知限制

已用现有千刀 API Key 只读验证 `/v1/models` 和 `/v1/usage` 返回成功，未执行线上聊天测试。Priority 字段到达模拟上游不等于千刀对具体账号兑现 Priority。完整响应缓存仍受客户端默认等待限制。模型刷新和用量查看可能由 Magpie 登录、启动及原生界面触发；dao 没有额外轮询。
