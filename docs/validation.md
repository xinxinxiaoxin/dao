# 0.1.0-rc.2 验证记录

日期：2026-11-26。环境：Windows、Node.js 24.22.1、Magpie 0.1.4823。测试使用独立配置、本机模拟千刀和虚构凭据。

## 核心逻辑

16 项测试通过，覆盖默认 7 次与限流间隔、错误分类、预算共享、同时重复调用、整段缓存、上下文超限、无请求标记的单次发送、跨实例并发、调低上限、队列取消与到期、Retry-After、上游取消、请求字段恢复、地址热改、手填模型、设置页保存、用户配置保留、模型移除、能力声明保留和设置端口占用时的聊天可用性。

## 新旧行为对照

旧网关基准为提交 `4119d7891fe4af0b978d1a238041e91f072c6b02`。六组对照检查实际发送次数、请求体与客户端响应体，全部一致。

| 场景 | 实际发送次数 |
| --- | --- |
| 正常回复 | 1 |
| 两次 429 后成功 | 3 |
| 200 中包含限流后成功 | 2 |
| 输出部分内容后断流，再次成功 | 2 |
| 空回复后成功 | 2 |
| 明确鉴权失败 | 1 |

对照缩短等待时间，不改变分类和计数规则。明确 `response.failed` 终态保留是新插件的已约定行为，另行测试。

## 真实宿主

- 无凭据时可加载插件；纯 Key 登录后内置及手填模型可收到正文。
- 原始 UA、会话头、缓存键、加密推理内容和 additional_tools 保留；选择的推理强度到达上游。
- Magpie 原生 Fast API 可对内置及手填模型开启 Priority，客户端不提供服务等级时同样生效；关闭后取消强制 Priority，重试保留原等级。
- 明确 Fast 拒绝只向上游发送一次，不降级重发，下一条 Fast 请求仍使用 Priority。
- 设置页保存后改变实际 Base URL；总并发热改为 1 后，四个并行请求最多一个在途。
- 同一宿主内删除设置页模型后刷新列表，已删除模型消失；供应商中手填的其他模型保留。
- 插件宿主重载时，已有请求完成，新宿主等待共享名额，没有超过总并发 1。
- 上下文超限以 `response.failed context_length_exceeded` 交付，一次上游发送。
- 持续 429 在宿主重复调用下仍只发送测试配置的 3 次。
- 客户端取消关闭上游连接。

发布包验收使用同一归档内的实现，隔离入口将重试次数改为 3、缩短等待以观察两层计数。默认 7 次和正式间隔由核心测试验证。

## 界面
