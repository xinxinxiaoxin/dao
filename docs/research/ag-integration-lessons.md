# AG 插件的接入经验

来源：[喜鹊ag网关](codex://threads/01a2129f-a7a6-7212-ba64-aa44f7927c8c) 的用户反馈、修复结果，以及当前 AG 工程的真实宿主测试。这些是验收依据，千刀的重试次数和错误分类以千刀需求为准。

## 配置必须改变实际请求

- Base URL 需要可编辑，并进入真正发送请求的 loader。不能让其他配置看起来可改，loader 却仍指向固定域名。
- 聊天 API Key 输入框必须出现在实际登录流程中。额外的余额凭据不能替代聊天 Key。
- 使用宿主已有的模型输入入口；填了模型名就应具备请求路由，不能因为远程模型列表失败而变成“没有可用端点”。
- 推理档位要检查 Codex 实际收到的模型目录，以及上游实际收到的 effort。插件内部声明正确不足以证明客户端可用。
- 真实客户端 UA 要逐次透传，多个客户端交替时不能复用上一条请求的值。

## 验收以客户端结果为准

- 登录成功、显示一个模型、发出了请求，都不能单独证明对话接通。需检查客户端收到的正文、工具调用及终止事件。
- 用本地模拟上游统计次数，验证 Magpie 重复调用 Provider 时，插件预算不会重新开始。
- 验证打包后的插件在干净宿主配置中可安装、可登录和可聊天，避免测试只覆盖开发入口。
- 当前请求的 UA、缓存字段和推理参数应分别检查；不能用“认出了 Codex”代替“保留了 Codex 发来的字段”。

## 问题定位

模型列表请求失败不自动等于聊天 Key 无效。已有对话切换后失败，也不自动等于插件只能用于新对话；应核对实际协议、请求大小和具体上游错误。

## 已知限制

AG 的测试结果不构成千刀插件已经可用的证据。新插件仍需覆盖可编辑 Base URL、共用并发池、千刀错误分类和当前 Magpie 版本。
